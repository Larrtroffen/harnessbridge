# HarnessBridge v1.7.1 — DSH workspace preservation fix

**Release date:** 2026-11-01
**Artifacts:** arm64 + x86_64 DMGs/ZIPs + `SHA256SUMS.txt`

## Fixed

- **DSH→DSH migration lost workspace membership.** DSH discovers session files by directory scan, but after `workspace.json` has `initialized: true` it does **not** adopt new files into existing workspaces; the session appears under **Ungrouped**. Registration was previously opt-in and the one-click path never passed it.
- DSH installs now **auto-register** the session into the workspace whose canonical `path == header.cwd`:
  - single-session wizard default is on for DSH targets;
  - one-click migrate-all passes registration for DSH automatically;
  - CLI `asi migrate` / `migrate-all` default to registration for `--to dsh` (`--no-register` opts out).
- Added **repair** for sessions migrated by older builds:
  - CLI: `asi dsh-workspaces --dsh-home ~/.dsh --json` (dry-run), `--fix` to write (requires DSH closed);
  - App: **Settings → DeepSeek Harness 工作区 → 修复工作区归属**.
  - Repair only attaches exact `realpath(header.cwd) == workspace.path` matches; nested/other-workspace cwd is reported as `path-mismatch`, not moved (DSH would filter it).
- Tests: `tests/test_dsh_workspace.py` (registration idempotency, orphan repair, workspace creation); app self-test unchanged.

## Notes

- Always quit DeepSeek Harness before writing `workspace.json`; the running app keeps workspace state in memory and can overwrite external edits.
- Export mode (`--mode export`) cannot carry DSH workspace.json/projection cache; only direct install repairs project grouping.
- All conversion/coverage numbers unchanged.
