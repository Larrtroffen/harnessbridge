**Release date:** 2026-10-31

## Welcome aboard

HarnessBridge moves **AI agent sessions** between coding harnesses — Claude Code, Codex, DeepSeek Harness, OMP, Qoder, Pi, Gemini CLI and 40+ formats covered by adapters. It is a native SwiftUI macOS app plus the `asi` CLI (the single conversion/migration engine).

v1.5.1 is the **first public GitHub release**: new name, a glass-refined native UI, and a **self-contained Apple-silicon app**.

## Highlights

- **New name, same ferry:** `HarnessBridge.app`, bundle id `io.github.larrtroffen.harnessbridge`. The CLI stays `asi`.
- **Liquid Glass UI** on macOS 26+ (with material/NSVisualEffectView fallback on macOS 13–25, Reduce Motion and Reduce Transparency respected).
- **Self-contained arm64 DMG** — bundles Python 3.12, the `asi` backend and `zstd`; no Python, zstd or repo checkout required to run the app. Gatekeeper note: ad-hoc signed and **not notarized**.
- **Direct install by default:** writes into the target harness's own store. DSH / Claude Code / OMP are stable; Codex / Qoder / Pi / Gemini are experimental; Goose is export-only.
- **Keep or move — always reversible:** `move` renames the source only after a verified install to `*.migrated-<timestamp>.bak`; nothing is deleted; `migrate-restore` / the app bring it back.
- **One-click full migration:** all other detected harnesses → one target, with limits, `--since-days`, dry-run plans, duplicate skipping, overwrite backups, progress, cancellation, per-session results and an atomic incremental journal.
- **Safer writes:** staging + atomic rename, post-install verification, rollback on failure, `--dry-run` zero writes, `--yes` required for real-store installs.
- **Local only:** no network, no telemetry, no accounts.

## Install

1. Download `HarnessBridge-1.5.1-macos-arm64.dmg` (or `.zip`) from this release.
2. Verify `shasum -a 256 -c SHA256SUMS.txt`.
3. Open the DMG, drag **HarnessBridge.app** to `/Applications`.
4. First launch is ad-hoc signed: right-click → **Open**, or `xattr -dr com.apple.quarantine /Applications/HarnessBridge.app`.
5. Optional source build:
   ```bash
   git clone https://github.com/Larrtroffen/harnessbridge.git
   cd harnessbridge/tools/HarnessBridgeApp
   swift build -c release && ./build.sh && open dist/HarnessBridge.app
   ```
   `./build.sh` defaults to a portable build (downloads the pinned Python runtime into `vendor/`); `./build.sh --dev` uses the repo backend directly.

## Verification

- **Backend:** 81 unit tests green locally (isolated `HOME`/env stores; tests requiring local harness data are not run on hosted CI). The bundled coverage artifacts are included in the app.
- **App:** `--self-test` **31 PASS / 0 FAIL** both in the repo build and from the mounted DMG (`portable: true`), including isolated install/verify, keep, backend move + restore, migrate-all dry-run, cancellation, brand/data-directory checks and performance baselines.
- **Real stores:** no real user store writes during tests; the app only reads sources unless you explicitly migrate.

## Known limitations

- Ad-hoc signed / not notarized; first launch needs the right-click flow.
- Codex/Qoder/Pi/Gemini direct install is experimental (target tools may need a restart / index rebuild).
- Directory/multi-file session sources are not moved (`keep` is enforced with a clear message).
- Token usage is shown when the source records it; some harnesses do not.
