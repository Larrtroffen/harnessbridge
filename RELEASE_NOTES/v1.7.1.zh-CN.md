# HarnessBridge v1.7.1 — 修复 DSH 工作区归属

**发布日期：** 2026-11-01
**产物：** arm64 / x86_64 DMG、ZIP、`SHA256SUMS.txt`

## 修复

- **DSH→DSH 迁移丢失工作区归属**：DSH 通过扫描 sessions 目录发现文件，但 `workspace.json` 的 `initialized` 为 true 后不会自动把新文件收养进已有 workspace，导致侧边栏显示 **Ungrouped**。之前的 `--register` 是可选参数，一键迁移也没有传，因此 DSH→DSH 容易丢工作区。
- 现在 DSH 安装会**默认注册**到 `realpath(header.cwd) == workspace.path` 的对应 workspace：
  - 单会话迁移向导：DSH 目标默认开启；
  - 一键迁移：DSH 目标自动传注册；
  - CLI `asi migrate` / `migrate-all`：`--to dsh` 默认注册，`--no-register` 可关闭。
- 新增旧迁移修复：
  - CLI：`asi dsh-workspaces --dsh-home ~/.dsh --json`（dry-run）、`--fix` 写入（需先退出 DSH）；
  - App：**设置 → DeepSeek Harness 工作区 → 修复工作区归属**。
  - 只修复精确 `realpath(header.cwd) == workspace.path` 的匹配；嵌套在其他 workspace 路径下的 cwd 会报告 `path-mismatch`，不会强行移动。
- 测试：`tests/test_dsh_workspace.py`（注册幂等、孤儿修复、创建 workspace）；App self-test 不变。

## 注意

- 写 `workspace.json` 前必须先退出 DeepSeek Harness，否则运行中的内存态可能覆盖外部修改。
- 导出模式不包含 DSH 的 workspace.json/projcache，只有直接安装才能修复项目分组。
- 转换与覆盖数字不变。
